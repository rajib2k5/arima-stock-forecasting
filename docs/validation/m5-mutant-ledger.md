# Milestone 5 mutant ledger

Validation row 2 (a hand mutant per new or changed test). Date: 2026-11-09. Base: commit 0bfd7ba (milestone 4) plus the
uncommitted milestone-5 working tree (the later commit 3cecee2 adds only `docs/validation/m5-preregistration.md`).

**How.** The repository was cloned into a private folder, the working tree was copied over the clone (tracked and untracked
files that are not ignored), then `uv sync` and, in `app/`, `npm ci --offline --no-audit --no-fund` were run. Every mutant is
one string replacement in one production file of that private copy, never in the shared tree. For each mutant the runner
checks the file is byte-identical to its original, applies the change, runs the command shown, records the exit status and the
names of the failing tests, writes the original bytes back and checks them, then re-runs the same command unmutated and
records that it passes. Before the runs the copy passed `uv run pytest -q` (2078 passed, 1 skipped) and `npx vitest run`
in `app/` (51 files, 1657 tests passed). Environment: `OPENBLAS_NUM_THREADS=1`, `VOL_DATA_DIR=<copy>/data` (that folder does
not exist in the copy; the baseline run had 1 skip).

Commands run from the copy's root, except those marked `app/:`, which run from `app/`. A test counts as killed when it is
among the failing tests of its command (a name in the column "Test" is the failing test as the runner printed it).

The tests of `tests/test_block_inference.py` and `tests/test_comparison_inference.py` are not here: they have their own
ledger, `docs/validation/m5-row5-mutants.md`.

**Items.** A new or changed test function counts once; a parametrized test counts once per new or changed case; each new
case of the shared corpus (`app/src/test/fixtures/payload_cases.json`: 16 in `cases`, 16 in `size_cases`) counts once per
reader (Python and TypeScript). One mutant may kill several items, and an item may list more than one killing mutant.
